# Programmatic API

<ApiMeta addedVersion="0.12.0" />

This section describes the programmatic API provided by [@rstest/core](https://github.com/web-infra-dev/rstest/tree/main/packages/core). You can use these JavaScript APIs to create Rstest instances, run or list tests, start watch sessions, and merge blob reports.

All programmatic APIs are exported from the `@rstest/core/api` entry:

```ts
import { createRstest } from '@rstest/core/api';
```

:::warning
All exports are currently experimental and may change before Rstest 1.0.0. Pin `@rstest/core` to an exact version for now to ensure API stability.
:::

## createRstest

The `createRstest` function creates and returns an Rstest instance. It resolves `config` once during instance creation and reuses it as the instance's base config. Options passed to instance methods apply to the current operation without mutating the base config.

`createRstest` always sets `RSTEST=true` in the host environment. It defaults `NODE_ENV` to `test` only when unset and preserves an existing value. Neither process-level assignment is snapshotted or restored.

- **Type:**

```ts
interface LoadedRstestConfig {
  /** Loaded config content. */
  content: RstestConfig;
  /** Source config file path returned by `loadConfig`, or `null`. */
  filePath: string | null;
}

interface CreateRstestOptions {
  cwd?: string;
  config?: RstestConfig | LoadedRstestConfig;
}

function createRstest(options?: CreateRstestOptions): Promise<RstestInstance>;
```

`cwd` defaults to `process.cwd()` and is the base for resolving a relative `config.root`. Omitting `config` uses an empty inline config; it does not load a config file from `cwd`.

### Inline config

Pass `config` to create an instance from an inline Rstest config.

- **Example:**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  cwd: './packages/app',
  config: {
    include: ['src/**/*.test.ts'],
    reporters: [],
  },
});

const result = await rstest.run();
console.log(result.ok);
```

### Load a config file

`createRstest` does not discover or load `rstest.config.*`; hosts that load a config file with `loadConfig` can pass its return value (`{ content, filePath }`) directly as `config`.

- **Example:**

```ts
import { loadConfig } from '@rstest/core';
import { createRstest } from '@rstest/core/api';

const cwd = './packages/app';
const loaded = await loadConfig({ cwd });
const rstest = await createRstest({
  cwd,
  config: loaded,
});
```

## rstest.context

`rstest.context` is a read-only object that provides information resolved when the instance is created.

- **Type:**

```ts
interface RstestProjectSummary {
  /** Project name. */
  name: string;
  /** Absolute project root path. */
  root: string;
  /** Project config file path, when one is associated with the project. */
  configFilePath?: string;
}

interface RstestInstanceContext {
  readonly version: string;
  readonly root: string;
  readonly config: Readonly<ResolvedRstestConfig>;
  readonly projects: readonly RstestProjectSummary[];
}
```

### context.version

The version of `@rstest/core` currently in use.

- **Type:** `string`

### context.root

The absolute root path of the Rstest instance. It is resolved from `config.root`, using `cwd` as the base for a relative value.

- **Type:** `string`

### context.config

The resolved config of the Rstest instance.

- **Type:** `Readonly<ResolvedRstestConfig>`

### context.projects

Summaries of the explicitly configured projects. The array is empty when the root config creates only the implicit default project.

- **Type:** `readonly RstestProjectSummary[]`

## rstest.run

`rstest.run()` runs one test cycle and returns a `TestRunResult`. Test failures, build failures, and errors while resolving the operation's config are represented by `ok: false` instead of rejecting the promise.

- **Type:**

```ts
interface CreateRunnerOptions {
  filters?: string[];
  filterMode?: 'fuzzy' | 'exact';
  related?: boolean;
  changed?: boolean | string;
  shard?: string | { index: number; count: number };
  project?: string[];
}

interface RunnerCycleOptions {
  filters?: string[];
  filterMode?: 'fuzzy' | 'exact';
  /** Pattern used to select tests by name. */
  testNamePattern?: RegExp | string;
  update?: boolean;
  /** Number of test failures allowed before stopping the cycle. */
  bail?: number | boolean;
  /** Whether the cycle succeeds when no tests match. */
  passWithNoTests?: boolean;
}

interface RunOptions extends CreateRunnerOptions, RunnerCycleOptions {}

interface RstestInstance {
  run(options?: RunOptions): Promise<TestRunResult>;
}
```

### Select test files

The following options choose the files to compile:

- `filters` uses case-insensitive substring matching by default. Set `filterMode: 'exact'` for normalized path equality. Omit `filters` to select all files; an explicit empty array selects none in either mode.
- `related` treats `filters` as source files and selects their related tests.
- `changed` selects tests related to working tree changes, optionally since a Git ref.
- `changed: false` disables changed-file selection.
- `shard` accepts the CLI-style `"1/3"` form or `{ index: 1, count: 3 }`.
- `project` supports project names, `*` wildcards, and `!` exclusions.

The remaining options apply only to the current cycle. `update: false` explicitly disables snapshot updates; omitting `update` keeps the configured or default mode. A reusable runner makes the build-time and runtime distinction explicit.

Browser projects are supported by `rstest.run()`.

### TestRunResult

- **Type:**

```ts
interface SerializedError {
  /** Error class name. */
  name: string;
  /** Error message. */
  message: string;
  /** Serialized stack trace. */
  stack?: string;
  /** Formatted assertion diff. */
  diff?: string;
  /** Serialized actual assertion value. */
  actual?: string;
  /** Serialized expected assertion value. */
  expected?: string;
  /** Retry attempt that produced this error. */
  retryCount?: number;
  /** Serialized error cause. */
  cause?: SerializedError;
}

interface TestResult {
  /** Final result status. */
  status: TestResultStatus;
  /** Display name of the test or test file. */
  name: string;
  /** Path of the owning test file. */
  testPath: string;
  /** Names of the enclosing suites. */
  parentNames?: string[];
  /** Execution duration in milliseconds. */
  duration?: number;
  /** Errors from the final attempt. */
  errors?: SerializedError[];
  /** Errors from earlier retry attempts. */
  retryErrors?: SerializedError[];
  /** Number of retry attempts performed. */
  retryCount?: number;
  /** Project name. */
  project: string;
  /** Serializable metadata attached to the task. */
  meta?: TaskMeta;
}

interface TestFileResult extends TestResult {
  /** Results of tests declared in this file. */
  results: TestResult[];
}

interface TestRunResult {
  ok: boolean;
  /** Results of test files executed in this cycle. */
  files: TestFileResult[];
  /** Aggregated result counts for this cycle. */
  stats: {
    /** Counts grouped by test status. */
    tests: {
      /** Total number of tests. */
      total: number;
      /** Number of passed tests. */
      passed: number;
      /** Number of failed tests. */
      failed: number;
      /** Number of skipped tests. */
      skipped: number;
      /** Number of todo tests. */
      todo: number;
    };
    /** Counts for test files. */
    files: {
      /** Total number of test files. */
      total: number;
      /** Number of failed test files. */
      failed: number;
    };
  };
  /** Errors not attributed to an individual test. */
  unhandledErrors: SerializedError[];
  /** Cycle duration. */
  duration: {
    /** Total duration in milliseconds. */
    total: number;
  };
  snapshot?: SnapshotSummary;
  coverage?: CoverageMapData;
}
```

`ok` is `true` only when no test or file failed, there are no unhandled errors, the cycle did not fail because no tests matched, and no other subsystem raised the instance exit status. The last condition includes failures such as a coverage threshold or `globalSetup` teardown failure.

`snapshot` is absent only when execution stops before a run begins. `coverage` is present when coverage is enabled.

Errors are projected into JSON-safe objects; internal reporter error classes are not exposed.

### Example

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const result = await rstest.run({
  filters: ['src/foo.test.ts'],
  filterMode: 'exact',
});

console.log(result.ok);
console.log(result.stats.tests);
```

## rstest.createRunner

:::tip
For most integrations, use `createRstest()` and call `rstest.run()`. Reach for `rstest.createRunner()` only when you need fine-grained lifecycle control.
:::

Each `rstest.run()` performs its own build and releases its run resources when the call finishes. A runner instead builds once, keeps that build warm for repeated `runner.run()` cycles, lets each cycle narrow the built files or change cycle-level options, and releases resources when you explicitly call `runner.close()`.

- **Type:**

```ts
interface RunnerBuildResult {
  testFiles: string[];
}

type RunnerRunOptions = RunnerCycleOptions;

interface RstestRunner {
  build(): Promise<RunnerBuildResult>;
  run(options?: RunnerRunOptions): Promise<TestRunResult>;
  close(): Promise<void>;
}

interface RstestInstance {
  createRunner(options?: CreateRunnerOptions): Promise<RstestRunner>;
}
```

Call `runner.build()` exactly once before `runner.run()`. Unlike one-shot `rstest.run()`, a compilation failure rejects `runner.build()` so the host can distinguish a build that never reached test reporting.

Runtime `filters` can only narrow the files returned by `runner.build()`; they cannot add a file that was not compiled. Runtime options are restored after every cycle and do not leak into later runs.

`runner.close()` is idempotent and runs pending `globalSetup` teardown. It rejects if teardown fails, and repeated calls observe the same result. `runner.build()` and `runner.run()` reject after closure. If `globalSetup` fails, later `runner.run()` calls return the same failed state without running tests; create a new runner to retry setup. `rstest.createRunner()` rejects browser configurations and the blob reporter; use one-shot `rstest.run()` for browser projects or blob reports.

- **Example:**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const runner = await rstest.createRunner({
  filters: ['src/'],
});

try {
  const { testFiles } = await runner.build();
  console.log(`Built ${testFiles.length} files`);

  const unitResult = await runner.run({
    testNamePattern: 'unit',
  });
  const allBuiltResult = await runner.run();
} finally {
  await runner.close();
}
```

## rstest.watch

Starts a Node watch session and returns a watcher that closes it.

- **Type:**

```ts
interface WatchOptions {
  onResult?: (result: TestRunResult) => void;
}

interface RstestWatcher {
  close(): Promise<void>;
}

type RstestWatchHandle = RstestWatcher;

interface RstestInstance {
  watch(options?: WatchOptions & RunOptions): Promise<RstestWatcher>;
}
```

`onResult` runs after every completed cycle, including the initial cycle. Its result is cycle-scoped: `files` and `stats` contain only files that actually ran in that cycle. To maintain session state, merge results by `testPath` in the host.

Errors thrown by `onResult` are isolated and do not stop the watch session. Calling `watcher.close()` releases the compiler, workers, file watchers, and pending `globalSetup` teardown.

Because they select a fixed test set for a one-shot run, enabled `related` and `changed` selectors are rejected by `rstest.watch()`. `changed: false` is treated as disabled. Use `rstest.run()` for enabled selectors.

Programmatic browser watch is not supported yet and rejects during startup. Use `rstest.run()` for one-shot browser execution.

- **Example:**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const watcher = await rstest.watch({
  onResult(result) {
    console.log(
      result.ok,
      result.files.map((file) => file.testPath),
    );
  },
});

await watcher.close();
```

## rstest.listTests

Collects test files and test declarations without running test bodies.

- **Type:**

```ts
interface ListOptions {
  filesOnly?: boolean;
  includeSuites?: boolean;
  printLocation?: boolean;
}

interface ListedTest {
  /** Path of the test file. */
  file: string;
  name?: string;
  taskName?: string;
  parentNames?: string[];
  project?: string;
  location?: Location;
  runMode?: 'skip' | 'todo';
  /** Entry kind. */
  type: 'file' | 'suite' | 'case';
}

interface RstestInstance {
  listTests(options?: ListOptions & RunOptions): Promise<ListedTest[]>;
}
```

Set `filesOnly` to skip collecting declarations. `includeSuites` includes named suites as separate entries. `printLocation` adds source locations.

`rstest.listTests()` rejects when collection fails instead of returning a partial or empty list.

`project` is present only when more than one project is configured. `taskName` is the declaration's own name, while `name` includes its suite prefix; `parentNames` provides the hierarchy without parsing that display name. Skipped and todo declarations are included with `runMode` set to `skip` or `todo`; runnable declarations omit `runMode`.

`rstest.listTests()` intentionally ignores `shard`, even when it is present in `RunOptions`. This differs from `rstest list --shard`, which lists only the selected shard.

- **Example:**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const tests = await rstest.listTests({
  includeSuites: true,
  printLocation: true,
});

console.log(tests);
```

## rstest.mergeReports

`rstest.mergeReports()` merges blob reports and returns the same result model as `rstest.run()`.

- **Type:**

```ts
interface MergeReportsOptions {
  path?: string;
  cleanup?: boolean;
}

interface RstestInstance {
  mergeReports(options?: MergeReportsOptions): Promise<TestRunResult>;
}
```

`path` selects the blob-report directory. `cleanup` removes consumed reports after a successful merge.

- **Example:**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest();

const result = await rstest.mergeReports({
  path: './.rstest-reports',
  cleanup: true,
});

console.log(result.ok);
```

## runCLI

Use `runCLI` when an embedding needs complete CLI parsing and process-oriented behavior rather than host-safe instance methods.

- **Type:**

```ts
interface RunCLIOptions {
  argv?: string[];
}

function runCLI(options?: RunCLIOptions): void;
```

`argv` contains the command, filters, and flags exactly as you would type them after `rstest` on the command line. It defaults to `process.argv.slice(2)`.

See the [CLI documentation](/guide/basic/cli) for all available commands and flags.

`runCLI` is exported from `@rstest/core/api`, not from the main `@rstest/core` entry.

- **Example:**

```ts
import { runCLI } from '@rstest/core/api';

runCLI({
  argv: ['run', 'src/foo.test.ts', '--update'],
});
```
