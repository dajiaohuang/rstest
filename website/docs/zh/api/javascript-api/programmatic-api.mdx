# 编程式 API

<ApiMeta addedVersion="0.12.0" />

本章节介绍 [@rstest/core](https://github.com/web-infra-dev/rstest/tree/main/packages/core) 提供的编程式 API。用户可以通过这些 JavaScript API 创建 Rstest 实例、运行或列出测试、启动监听会话，以及合并 blob 报告。

所有的编程式 API 从 `@rstest/core/api` 入口导出：

```ts
import { createRstest } from '@rstest/core/api';
```

:::warning
目前所有导出目前都是实验性的，在 Rstest 1.0.0 之前可能发生变化。请暂时锁定 `@rstest/core` 的精确版本来保证 API 稳定性。
:::

## createRstest

`createRstest` 函数用于创建并返回一个 Rstest 实例。`config` 会在创建实例时解析一次，并作为实例的基础配置持续复用。传给实例方法的选项只应用于当前操作，不会修改这份基础配置。

`createRstest` 始终在宿主环境中设置 `RSTEST=true`。仅当 `NODE_ENV` 尚未设置时，才将其默认设为 `test`；已有值不会被覆盖。Rstest 不会对这两项进程级设置进行快照或恢复。

- **类型：**

```ts
interface LoadedRstestConfig {
  /** 已加载的配置内容。 */
  content: RstestConfig;
  /** `loadConfig` 返回的配置文件来源路径，没有时为 `null`。 */
  filePath: string | null;
}

interface CreateRstestOptions {
  cwd?: string;
  config?: RstestConfig | LoadedRstestConfig;
}

function createRstest(options?: CreateRstestOptions): Promise<RstestInstance>;
```

`cwd` 默认为 `process.cwd()`，并作为相对 `config.root` 的解析基准。省略 `config` 会使用空的内联配置，不会从 `cwd` 加载配置文件。

### 内联配置

通过 `config` 传入内联 Rstest 配置来创建实例。

- **示例：**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  cwd: './packages/app',
  config: {
    include: ['src/**/*.test.ts'],
    reporters: [],
  },
});

const result = await rstest.run();
console.log(result.ok);
```

### 加载配置文件

`createRstest` 不会发现或加载 `rstest.config.*`；宿主可通过主入口的 `loadConfig` 自行加载配置文件，并将返回值（`{ content, filePath }`）直接作为 `config` 传入。

- **示例：**

```ts
import { loadConfig } from '@rstest/core';
import { createRstest } from '@rstest/core/api';

const cwd = './packages/app';
const loaded = await loadConfig({ cwd });
const rstest = await createRstest({
  cwd,
  config: loaded,
});
```

## rstest.context

`rstest.context` 是一个只读对象，提供创建实例时解析出的信息。

- **类型：**

```ts
interface RstestProjectSummary {
  /** 项目名称。 */
  name: string;
  /** 项目的绝对根路径。 */
  root: string;
  /** 与项目关联的配置文件路径（如果有）。 */
  configFilePath?: string;
}

interface RstestInstanceContext {
  readonly version: string;
  readonly root: string;
  readonly config: Readonly<ResolvedRstestConfig>;
  readonly projects: readonly RstestProjectSummary[];
}
```

### context.version

当前使用的 `@rstest/core` 版本。

- **类型：** `string`

### context.root

Rstest 实例的绝对根路径。它由 `config.root` 解析得出；当 `config.root` 为相对路径时，以 `cwd` 为基准。

- **类型：** `string`

### context.config

Rstest 实例解析后的配置。

- **类型：** `Readonly<ResolvedRstestConfig>`

### context.projects

显式配置的项目摘要。当根配置只创建隐式默认项目时，此数组为空。

- **类型：** `readonly RstestProjectSummary[]`

## rstest.run

`rstest.run()` 会运行一个测试轮次，并返回 `TestRunResult`。测试失败、构建失败和操作期间的配置解析错误会通过 `ok: false` 表示，而不会导致 Promise 被拒绝。

- **类型：**

```ts
interface CreateRunnerOptions {
  filters?: string[];
  filterMode?: 'fuzzy' | 'exact';
  related?: boolean;
  changed?: boolean | string;
  shard?: string | { index: number; count: number };
  project?: string[];
}

interface RunnerCycleOptions {
  filters?: string[];
  filterMode?: 'fuzzy' | 'exact';
  /** 用于按名称选择测试的模式。 */
  testNamePattern?: RegExp | string;
  update?: boolean;
  /** 停止当前轮次前允许的测试失败数。 */
  bail?: number | boolean;
  /** 没有匹配测试时当前轮次是否成功。 */
  passWithNoTests?: boolean;
}

interface RunOptions extends CreateRunnerOptions, RunnerCycleOptions {}

interface RstestInstance {
  run(options?: RunOptions): Promise<TestRunResult>;
}
```

### 选择测试文件

以下选项决定需要编译的文件：

- `filters` 默认使用不区分大小写的子字符串匹配。设置 `filterMode: 'exact'` 后会使用规范化路径全等匹配。省略 `filters` 时选择所有文件；显式传入空数组时，两种模式都不会选择任何文件。
- `related` 将 `filters` 视为源文件，并选择与其关联的测试。
- `changed` 选择与工作区变更相关的测试，也可以指定一个起始 Git 引用。
- `changed: false` 会禁用 `changed` 文件选择。
- `shard` 接受 CLI 风格的 `"1/3"` 或 `{ index: 1, count: 3 }`。
- `project` 支持项目名称、`*` 通配符和 `!` 排除项。

其余选项只应用于当前轮次。`update: false` 会显式禁用快照更新；省略 `update` 时会保留配置或默认模式。可复用运行器会显式区分构建期和运行期。

`rstest.run()` 支持浏览器项目。

### TestRunResult

- **类型：**

```ts
interface SerializedError {
  /** 错误类名称。 */
  name: string;
  /** 错误信息。 */
  message: string;
  /** 序列化后的调用栈。 */
  stack?: string;
  /** 格式化后的断言差异。 */
  diff?: string;
  /** 序列化后的断言实际值。 */
  actual?: string;
  /** 序列化后的断言预期值。 */
  expected?: string;
  /** 产生此错误的重试次数。 */
  retryCount?: number;
  /** 序列化后的错误原因。 */
  cause?: SerializedError;
}

interface TestResult {
  /** 最终结果状态。 */
  status: TestResultStatus;
  /** 测试或测试文件的显示名称。 */
  name: string;
  /** 所属测试文件的路径。 */
  testPath: string;
  /** 外层测试套件的名称。 */
  parentNames?: string[];
  /** 执行时长（毫秒）。 */
  duration?: number;
  /** 最后一次执行产生的错误。 */
  errors?: SerializedError[];
  /** 之前重试产生的错误。 */
  retryErrors?: SerializedError[];
  /** 已执行的重试次数。 */
  retryCount?: number;
  /** 项目名称。 */
  project: string;
  /** 关联到任务的可序列化元数据。 */
  meta?: TaskMeta;
}

interface TestFileResult extends TestResult {
  /** 当前文件中声明的测试结果。 */
  results: TestResult[];
}

interface TestRunResult {
  ok: boolean;
  /** 当前轮次执行的测试文件结果。 */
  files: TestFileResult[];
  /** 当前轮次的汇总结果数量。 */
  stats: {
    /** 按测试状态分组的数量。 */
    tests: {
      /** 测试总数。 */
      total: number;
      /** 通过的测试数量。 */
      passed: number;
      /** 失败的测试数量。 */
      failed: number;
      /** 跳过的测试数量。 */
      skipped: number;
      /** todo 测试数量。 */
      todo: number;
    };
    /** 测试文件数量。 */
    files: {
      /** 测试文件总数。 */
      total: number;
      /** 失败的测试文件数量。 */
      failed: number;
    };
  };
  /** 未归属于单个测试的错误。 */
  unhandledErrors: SerializedError[];
  /** 当前轮次的执行时长。 */
  duration: {
    /** 总时长（毫秒）。 */
    total: number;
  };
  snapshot?: SnapshotSummary;
  coverage?: CoverageMapData;
}
```

只有在没有测试或测试文件失败、没有未处理错误、当前轮次未因找不到测试而失败，并且其他子系统没有提高实例退出状态时，`ok` 才为 `true`。最后一项涵盖覆盖率阈值或 `globalSetup` 清理失败等情况。

只有在测试运行开始前终止执行时，`snapshot` 才会缺失。启用覆盖率时会提供 `coverage`。

错误会被投影为可安全序列化为 JSON 的对象，不会暴露内部报告器错误类。

### 示例

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const result = await rstest.run({
  filters: ['src/foo.test.ts'],
  filterMode: 'exact',
});

console.log(result.ok);
console.log(result.stats.tests);
```

## rstest.createRunner

:::tip
对于大多数集成，使用 `createRstest()` 并调用 `rstest.run()` 即可。只有需要精细控制生命周期时，才使用 `rstest.createRunner()`。
:::

每次调用 `rstest.run()` 都会独立构建，并在调用结束时释放本次运行的资源。运行器则只构建一次，并在多次 `runner.run()` 之间复用该构建；每个轮次可以收窄已构建文件或调整轮次级选项，最后由宿主显式调用 `runner.close()` 释放资源。

- **类型：**

```ts
interface RunnerBuildResult {
  testFiles: string[];
}

type RunnerRunOptions = RunnerCycleOptions;

interface RstestRunner {
  build(): Promise<RunnerBuildResult>;
  run(options?: RunnerRunOptions): Promise<TestRunResult>;
  close(): Promise<void>;
}

interface RstestInstance {
  createRunner(options?: CreateRunnerOptions): Promise<RstestRunner>;
}
```

在 `runner.run()` 之前必须且只能调用一次 `runner.build()`。与一次性的 `rstest.run()` 不同，编译失败会使 `runner.build()` 返回的 Promise 被拒绝，以便宿主识别从未进入测试报告阶段的构建。

运行期 `filters` 只能收窄 `runner.build()` 返回的文件，不能加入未编译的文件。运行期选项会在每个轮次后恢复，不会泄漏到后续运行。

`runner.close()` 是幂等的，并会运行待处理的 `globalSetup` 清理函数。清理失败时，它返回的 Promise 会被拒绝；重复调用会得到相同结果。关闭后，`runner.build()` 和 `runner.run()` 返回的 Promise 都会被拒绝。如果 `globalSetup` 失败，后续 `runner.run()` 会直接返回相同的失败状态而不执行测试；如需重试初始化，请创建新的运行器。`rstest.createRunner()` 会拒绝浏览器配置和 blob 报告器；浏览器项目或 blob 报告请使用一次性的 `rstest.run()`。

- **示例：**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const runner = await rstest.createRunner({
  filters: ['src/'],
});

try {
  const { testFiles } = await runner.build();
  console.log(`Built ${testFiles.length} files`);

  const unitResult = await runner.run({
    testNamePattern: 'unit',
  });
  const allBuiltResult = await runner.run();
} finally {
  await runner.close();
}
```

## rstest.watch

启动 Node.js 监听会话，并返回用于关闭它的监听器。

- **类型：**

```ts
interface WatchOptions {
  onResult?: (result: TestRunResult) => void;
}

interface RstestWatcher {
  close(): Promise<void>;
}

type RstestWatchHandle = RstestWatcher;

interface RstestInstance {
  watch(options?: WatchOptions & RunOptions): Promise<RstestWatcher>;
}
```

每个已完成的轮次（包括初始轮次）之后，都会调用 `onResult`。结果按当前轮次统计：`files` 和 `stats` 只包含该轮次实际执行的文件。如需维护会话状态，请在宿主中按 `testPath` 合并结果。

`onResult` 抛出的错误会被隔离，不会停止监听会话。调用 `watcher.close()` 会释放编译器、worker、文件监听器，并运行待处理的 `globalSetup` 清理函数。

启用的 `related` 和 `changed` 选择器会为单次运行选择固定的测试集合，因此 `rstest.watch()` 会拒绝它们。`changed: false` 视为禁用。使用这些选择器时请调用 `rstest.run()`。

编程式浏览器监听暂不支持，并会在启动时拒绝。单次浏览器执行请使用 `rstest.run()`。

- **示例：**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const watcher = await rstest.watch({
  onResult(result) {
    console.log(
      result.ok,
      result.files.map((file) => file.testPath),
    );
  },
});

await watcher.close();
```

## rstest.listTests

收集测试文件和测试声明，但不运行测试主体。

- **类型：**

```ts
interface ListOptions {
  filesOnly?: boolean;
  includeSuites?: boolean;
  printLocation?: boolean;
}

interface ListedTest {
  /** 测试文件路径。 */
  file: string;
  name?: string;
  taskName?: string;
  parentNames?: string[];
  project?: string;
  location?: Location;
  runMode?: 'skip' | 'todo';
  /** 条目类型。 */
  type: 'file' | 'suite' | 'case';
}

interface RstestInstance {
  listTests(options?: ListOptions & RunOptions): Promise<ListedTest[]>;
}
```

设置 `filesOnly` 可跳过声明收集。`includeSuites` 会将具名测试套件作为独立条目返回。`printLocation` 会加入源码位置。

收集失败时，`rstest.listTests()` 返回的 Promise 会被拒绝，而不是返回部分列表或空列表。

只有配置多个项目时才会提供 `project`。`taskName` 是声明自身的名称，`name` 包含测试套件前缀；`parentNames` 提供层级，无需解析显示名称。标记为 `skip` 或 `todo` 的声明也会返回，`runMode` 分别为 `skip` 或 `todo`；可运行声明不提供 `runMode`。

即使 `RunOptions` 中存在 `shard`，`rstest.listTests()` 也会刻意忽略它。这与 `rstest list --shard` 不同，后者只列出选定分片。

- **示例：**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest({
  config: {
    include: ['src/**/*.test.ts'],
  },
});

const tests = await rstest.listTests({
  includeSuites: true,
  printLocation: true,
});

console.log(tests);
```

## rstest.mergeReports

`rstest.mergeReports()` 用于合并 blob 报告，并返回与 `rstest.run()` 相同的结果模型。

- **类型：**

```ts
interface MergeReportsOptions {
  path?: string;
  cleanup?: boolean;
}

interface RstestInstance {
  mergeReports(options?: MergeReportsOptions): Promise<TestRunResult>;
}
```

`path` 用于选择 blob 报告目录。`cleanup` 会在合并成功后删除已消费的报告。

- **示例：**

```ts
import { createRstest } from '@rstest/core/api';

const rstest = await createRstest();

const result = await rstest.mergeReports({
  path: './.rstest-reports',
  cleanup: true,
});

console.log(result.ok);
```

## runCLI

如果嵌入场景需要完整的 CLI 参数解析和面向进程的行为，而不是宿主安全的实例方法，请使用 `runCLI`。

- **类型：**

```ts
interface RunCLIOptions {
  argv?: string[];
}

function runCLI(options?: RunCLIOptions): void;
```

`argv` 包含在命令行中写在 `rstest` 之后的命令、过滤条件和选项。默认值为 `process.argv.slice(2)`。

所有可用的命令和选项，请参阅 [CLI 文档](/guide/basic/cli)。

`runCLI` 从 `@rstest/core/api` 导出，不再从 `@rstest/core` 主入口导出。

- **示例：**

```ts
import { runCLI } from '@rstest/core/api';

runCLI({
  argv: ['run', 'src/foo.test.ts', '--update'],
});
```
